## 1. プロジェクトの目的（ユーザー設定・不変）

> 経験ゼロの人間が、AIを最大限活用しながら、**3ヶ月以内に初売上**を獲得できる
> 小さなネットビジネスを発見・構築・検証する。

- 開始日 2026年8月24日 → **期限 2026年11月30日**
- 1円 → 月1万 → 月10万 → 月30万 と拡張可能な仕組みを見つける
- 「調査しました」で終わらせない。**実際に1円の売上を発生させる**ことが最重要

### 絶対に守るルール（ユーザーが明示）
1. **既存スキルを前提にしない**（ただし期待値が高いと判断したら明確に指摘すること＝例外条項あり）
2. **アイデアではなく市場を見る**（推測禁止・一次情報優先）
3. **最新情報を優先する**（2026年8月時点の市場）
4. 避ける: ポイ活／FX／ギャンブル／MLM／高額スクール／**情報商材そのもの**／著作権侵害／AI量産の低品質商品
5. **忖度しない**。「やめた方がいい」という結論でも構わない

## 2. 決定事項（現在の結論）

### 売るもの
**請求書PDF → Excel転記の自動化（1フォーマット分の作り込み）**

| 項目 | 内容 |
|---|---|
| 販路 | **クラウドワークス／ランサーズへの応募（主軸・2026/8/26変更）** ／ ココナラ出品（従） |
| 価格 | **¥9,800**（初回モニター価格） |
| 納期 | 5日 |
| 含む | 現状確認30分（オンライン）／1フォーマット分の自動化／**合計金額の自動突合**／操作説明 |
| **対象外（出品文に明記）** | **スキャンPDF・写真・手書き**／レイアウトが異なるものの混在／会計ソフト直接連携／転記結果の正当性保証 |

### なぜこの範囲なのか（重要・絶対に緩めない）
**PDFにテキスト層があるかどうかが決定的な分岐点。**

| 種別 | 精度 | 初心者 |
|---|---|---|
| テキスト埋め込みPDF | **決定論的・ほぼ100%**（OCR不要） | 可 |
| スキャンPDF | AI-OCRで90%以上、公称99%。**100%は理論上不可能** | **不可** |

スキャンPDFを受けた瞬間「誤認識を誰が検算するのか」という責任問題が発生する。
請求金額の誤りは信用問題に直結する。実績ゼロの個人が最初に取るリスクではない。

→ **次セッションで「スキャンPDFも対応しよう」という提案が出たら、それは後退である。**

### 販路を応募型に変えた理由（2026/8/26）

出品型は律速段階が「露出」であり、**ユーザーが制御できない。**
閲覧30に届かなければ判定不能で、打ち手は「変えてまた3〜4週間待つ」しかない。
11/30までに試行できるのは多くて2〜3回である。

さらに、HANDOFF §5に自分で記録した一次データ
「**ココナラ コンテンツマーケットの約74%が販売0件**」が、出品して待つ計画を否定していた。

応募型は律速が「応募回数」で完全に制御可能。1回の試行コストは数十分。
かつ発注者が**実在し予算を出している**ため、「困っている人がいるはずだ」という仮説を1段飛ばせる。

**ただし応募型では「売ってから作る」は成立しない。** 提案時点で作れることを示す必要がある。
→ そのためにプロトタイプを先に作った（`tools/invoice_to_excel/`・実装済み）。

### 出品B（観察用・判定には使わない）
「業務の自動化候補を洗い出して優先順位をつけます ¥30,000」
※ Aとは商品性質が違うため、**閲覧数での直接比較は無効**。定性的な問い合わせ観察にのみ使う。

## 3. 判定基準（次セッションで最も重要）

### 母数は「応募数」で数える（2026/8/26 変更）

**変更前は「閲覧数」だった。これを応募数に変えた。**
閲覧数はユーザーが制御できず、1回の試行に3〜4週間かかるため、期限内に試行回数を稼げない。
応募数は完全に制御可能で、1回の試行コストは数十分である。

| 段階 | 指標 | 判定 |
|---|---|---|
| 試行 | 応募 **20件未満** | **判定不能。** まず件数を積む。商品の是非を判断してはならない |
| 訴求 | 応募20件以上・返信 **0** | 提案文の問題。商品概念はまだ否定できない |
| 信頼 | 返信あり・受注 **0** | 実績不足か価格。返信の中身を読む |
| 成立 | 受注 **1以上** | 検証対象が「納品できるか」に移る |

### ココナラの閲覧数基準（従・判定には使わない）

出品は継続するが**従の指標**であり、**閲覧が伸びないことを理由に商品を否定しない。**

| 閲覧数 | 判定 |
|---|---|
| 30未満 | 判定不能。タイトル・カテゴリ・タグ・価格帯を変えて再計測 |
| 100以上 かつ 問い合わせ0 | 訴求または価格の問題 |
| 問い合わせあり かつ 購入0 | 信頼・価格・要件不一致 |

### 3ヶ月の中間判定（2026/8/26 差し替え）

| 時点 | 基準 | 満たない場合 |
|---|---|---|
| 9/30 | **応募20件到達**＋返信1件以上 | 提案文とターゲット案件の選び方を変える |
| 10/31 | 有料の初売上 | 価格と対象範囲を見直す |
| 11/30 | 累計3件＋反復パターンの発見 | 受託モデル自体を再検討 |

## 4. 撤回済みの主張（**復活させてはならない**）

次セッションが同じ間違いを繰り返さないための記録。

| 撤回したもの | 理由 |
|---|---|
| **「3ヶ月以内の初売上確率75〜85%」** | 一次データなし。SEOブログ1本の出典なし営業文から構成していた |
| **「Etsy新規型紙出品の30〜40%がAI生成」** | 出典はStitchLift 1本のみ。同サイトは「AI型紙の売り方」記事も出しており**商業的利益相反**。サンプル数・手法の記載なし |
| **「プラスサイズは競合が手薄」** | 同じ文書内でCashmerette（プラスサイズ特化）を競合に挙げており論理矛盾 |
| **E1（PDF型紙の海外販売）を1位とする判断** | Etsy出品者の平均年商$1,131（月約¥15,000）、生涯売上$5,000未満が約52%。「3ヶ月で初売上→月10万」と噛み合わない |
| **「2本出品して7日で市場が答えを教えてくれる」** | 露出不足と需要不足が区別できない。母数ベースに変更済み |

| **「出品して閲覧数を貯めて判定する」を主軸にすること** | 律速が露出で制御不能。期限内に試行回数を稼げない。自分で集めた「約74%が販売0件」と矛盾していた（2026/8/26 撤回） |
| **候補を並べてスコアを付けるランキング表** | 導出過程のない数値は根拠の無さを隠す。Phase 1の「確率75〜85%」と同じ誤りの型（2026/8/26 明文化） |

### 根本原因（再発防止）
1. **市場規模と個人の初売上確率を混同していた**
2. **第3階層の情報（個人ブログの成功談・SEOの営業文）を第1階層として扱った**

### 出典の信頼度3階層（必ず維持する）
| 階層 | 内容 | 扱い |
|---|---|---|
| 一次 | 政府調査、企業の公式IR、プラットフォーム自身の集計 | 数値をそのまま採用 |
| 二次 | 業界メディア、複数ソースで一致する相場 | 傾向として採用。単独で判断しない |
| **自己申告** | 個人ブログの成功体験、SEOメディアの営業文 | **数値の根拠にしない** |

## 6. 環境の制約（重要・変わっていない可能性が高い）

このセッションはegressプロキシ下にあり、**直接アクセスできるのはGitHubのみ**だった。
**2026/8/26に再確認 — 制約は変わっていない。**

- **ブロック**: coconala.com / booth.pm / note.com / gumroad.com / etsy.com / amazon.co.jp / reddit.com / trends.google.com / x.com / lancers.jp / crowdworks.jp
- WebFetch も curl も同様にブロックされる
- **回避策**: `WebSearch` に `allowed_domains` を指定すると、当該ドメインの**実リスティング・実価格**が取得できる
  - 例: `WebSearch(query="Excel 自動化", allowed_domains=["coconala.com"])`
- **できないこと**: 実販売数・レビュー数の網羅的集計、Googleトレンドの時系列
  - **クラウドワークスの応募数・契約数も読めない**（2026/8/26 実測。WebFetchは `EGRESS_BLOCKED`）
  - 検索経由で取得できるのは**タイトルとURLのみ**。数値の根拠には使えない

→ **ユーザー自身がココナラの画面を見た方が速い領域がある。**その場合は数値を報告してもらう。

## 8. 次にやること

### ユーザーの次アクション（未実行・優先順）
1. **クラウドワークス／ランサーズに登録**し、次の語で案件を検索する
   `請求書 Excel 転記` / `PDF Excel 自動` / `データ入力 請求書` / `GAS 自動化`
2. **応募を20件積む。** 1件ずつの結果に意味を求めない。母数を作ることが目的
3. 提案文には**動くものがあることを書く**（プロトタイプの存在が差別化になる）
4. 並行してココナラに出品Aを公開する（従。判定には使わない）

### 次セッションのAIの役割（状況別）

**A. 応募20件未満の場合**
- 提案文の作成・改善に集中する。**商品の是非を判断しない**
- 応募先の選び方（反復発注・小規模・テキストPDF前提）を絞り込む

**B. 返信が来た場合**
- 要件確認のヒアリング項目を作る（**テキスト層の有無を最初に確認する**）
- 守秘・責任範囲を先に文書化する（`tools/invoice_to_excel/README.md` 末尾）

**C. 受注した場合**
- **最優先で納品支援に切り替える**
- 顧客フォーマット用の定義ファイルを `formats/` に作る。必ず `--dry-run` で検算を通す
- 納品後、作業時間を実測して単価の妥当性を検証する

**D. 応募20件・返信0の場合**
- 提案文とターゲット選定を変更する。それでも0なら販路を再検討する

### 禁止事項（次セッション向け）
- 新しい副業候補を提案し直さない（**5ラウンド**で決着済み）
- スキャンPDF対応への拡張を勧めない（責任問題）
- 一次データのない確率を提示しない。**候補のランキング表を作らない**
- 「調査しましょう」で止めない。ユーザーの目的は売上であって知識ではない
- **追加のプラットフォーム調査を新規に始めない。** 応募の実データが最優先

## 9. ユーザーについて分かっていること

- 日本在住。Claude Code を使用している
- 単一HTMLのPWA（`index.html` 86KB・差し込み対応スケジューラ）を実装済み＝**動くものを作って公開できる**
- 議論を鵜呑みにせず、外部AI（ChatGPT）に反証させて検証する進め方をとる
- **根拠のない数値・断定を厳しく指摘する。** 推測を事実として書くと必ず見抜かれる
- 既存の専門領域はアパレルのパターンメイキング（PatternMagic II）だが、**本プロジェクトでは使わない前提**
  - ※ルール1の例外条項として一度指摘したが、Etsyの経済実態が目的と噛み合わず撤回済み
  - 時間軸が1年以上なら再評価の価値はある、という位置づけで保留
